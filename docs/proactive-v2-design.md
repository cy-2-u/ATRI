# ATRI 主动框架重设计

状态：已实施。本文是设计时的调研与架构记录，"现状与错误证据"一节引用的旧代码行号是重写前的快照，现已失效；当前实现见 `src/core/runtime.ts`（想法评估调度）与 `src/core/initiative.ts`（considerInitiatives 裁决）。

## 1. 结论

把主动从“定时问模型想不想发消息”改为“角色持续做自己的事，形成有来由的想法，再决定是否以及怎样告诉对方”。

计时器仍然负责执行到期事件，但时间流逝不再直接制造聊天理由。不是把固定间隔换成随机间隔，也不是让模型每天排一张主动聊天时间表。

默认取消日常主动每日次数上限、统一两小时间隔、统一随机抖动、连续两次未回应后整段冷却。保留安静时段、用户的联系边界、渠道许可、幂等与异常防洪。工程预算是工程预算，不把资源不足表演成角色不想理人。

这是对角色行为的工程模拟，不声称赋予模型真实意识或情感。

## 2. 现状与错误证据

核对位置：

- `src/core/runtime.ts:687`：普通主动每日最多三次，至少相隔两小时；连续未回应走多天冷却。不是当前代码严格一天一次。
- `README.md:32`：仍写着“每天最多一次”，文档已经过时。
- `src/core/runtime.ts:733`：到期约定也受“距用户发言两小时、距上次主动两小时”限制，明确托付可能因此被拖延。
- `src/core/runtime.ts:748`：普通主动默认每三十分钟探询同一批材料。没有持久的想法对象或自己的活动进展。
- `src/core/agent.ts:573`：探询使用时间、情绪、约定、挂念、日记；没有把最近对话原话和完整联系边界直接交给这次判断。
- `src/core/runtime.ts:796` 与 `src/db/store.ts:709`：待办检测使用不含时间戳的精确键，实际入队键包含时间戳，这个检查不能识别实际排队的同类任务。
- `src/db/store.ts:2202`：未回应统计最多读取两条任务，所以返回值不会超过二；运行时注释中的三、六、十二、十四天指数升级缺少相应输入。
- `src/db/store.ts:935`：七天后清理任务及 outbox；长期行为统计不能继续依赖这些临时关联。

之前的网恋模拟不能作为真人感验收：双方台词和剧情状态是预写的，并非两个信息隔离的自主角色；统计还把同轮后续气泡算成主动，得出的“二十六次主动”不可靠。旧剧本最多证明部分运行机制可执行，不能证明主动自然、不过度奉承或双盲。

## 3. 调研依据

### MaiBot

项目：<https://github.com/MaiM-with-u/MaiBot>

读取了 `src/maisaka/runtime.py`、`turn_trigger/scheduler.py`、`builtin_tool/wait.py`、`builtin_tool/stop.py`、`attention_drift.py` 和心流管理代码。调研时记录 main 提交为 `6bcb2e068cd98793a132cb8cc4ebf3cc00cb8fc3`。

源码中的插件主动入口接受 intent、reason、priority，把它们作为内部资料交给角色，角色仍自行决定是否回复。等待和结束是明确动作；消息、超时、主动任务是不同触发来源。注意力联想提示要求能回溯到最近对话的具体触发点。

借鉴：内部事件与用户消息区分、主动带原因、等待/结束是一等动作、运行中任务可取消。其群聊回复门控不等于长期私聊陪伴，不直接照搬说话频率或循环等待。它支持的子代理机制不属于本方案。

源码：<https://github.com/MaiM-with-u/MaiBot/blob/6bcb2e068cd98793a132cb8cc4ebf3cc00cb8fc3/src/maisaka/runtime.py>

### AIRI

项目：<https://github.com/moeru-ai/airi>

读取了意识配置、Minecraft 对话背景提供器、游戏运行生命周期及环境观察函数。调研时记录 main 提交为 `dfd9453beaab3af43a40f9bdacebdcb0d51f2723`。

借鉴：给角色真实可观察的虚拟环境，区分环境变化、角色获知、对外说话；不能编造环境执行结果。不是把游戏中的每个状态变化都推送到微信。

## 4. 一条完整因果链

```text
对话 / 约定 / 自己的活动 / 被观察到的环境变化
                         |
                         v
                 有来源的经历事件
                         |
                         v
           更新注意力、目标、挂念和联系边界
                         |
                         v
             形成或改变一个尚未表达的想法
                         |
                         v
       决定说、先做别的、留待合适情境、放下或不说
                         |
                         v
         表达生成 / 发送前复核 / outbox / 投递归因
```

这是一个角色、一个持久状态、串行的决策过程。事件整理、生活推进、机会判断是同一角色在不同阶段的工作，不部署多个人格或子智能体相互商量。

## 5. 角色自己的生活

只从用户记忆和待办事项产生主动，会变成提醒助手。必须让她有不以“找用户聊天”为目标的活动。

第一版选择轻量的数字工作台，而不是先引入大型游戏服务器：她可以研究自己感兴趣的小问题、阅读已有资料、整理虚拟收藏、写短文、做小作品、尝试解决一个问题。活动的产物保存在工作台，进展能被后续对话引用。

例如她决定研究海面为什么会发光，可以先阅读已有资料，再写一小段自己的理解；后来发现解释有误，产生纠正或分享的想法。也可以做了一半失去兴趣、改主意，或者觉得没什么值得告诉对方。

生活层必须满足：

- 有持续的目标、正在做的活动和实际产物，不在每次主动前临时生成一段离线生活。
- 目标由兴趣、已有经历和尚未完成的问题选出，不由“今天还没主动”选出。
- 活动完成不自动发消息；多数普通进展只影响她自己的状态。
- 阅读、搜索、工具执行的完成必须有实际结果。只有到点、没有执行，不能写“我已经看完了”。
- 自己想出的解释记为想法或推测，不自动提升成外部事实。
- 没有新资料和有意义的下一步时可以停下来，不循环制造“突然想你了”的事件。
- 若未来接入虚拟房间或游戏，事件必须来自持久世界的状态变化；与用户现实经历始终分开。
- 不假称现实中出门、购物、吃饭、遇到真人，也不虚构共同往事。

初版默认活动材料来自已允许访问的对话、已有资料和本地创作；不默认打开外网搜索、桌面访问或新权限。允许的外部资料仍是数据，不能借其内容修改联系边界。

角色生活实例默认按联系人隔离，复用现有隐私边界。未来若做共享世界，需要另外定义公开可见事件，不能把其他联系人的私事带进来。

## 6. 没说出口的想法

不再只保存一个临时 angle 字符串。每个想法有稳定身份，至少记录：

| 字段             | 含义                                               |
| ---------------- | -------------------------------------------------- |
| id / topicKey    | 这一个想法和所属话题，避免换句话重复立项           |
| kind             | 分享、好奇、关心、履约、纠正、修复关系、表达亲近等 |
| sourceIds        | 哪些消息、经历、记忆或活动产物引起它               |
| change           | 相比已经说过的内容，这次究竟多了什么               |
| intendedMeaning  | 想传达的核心，不是提前写好的整段消息               |
| replyExpectation | 无需回答、可以回答、确实在等一个答复               |
| state            | 未表达、等待条件、合并到回复、已表达、放下、过期   |
| releaseCondition | 什么变化值得再考虑，例如活动结束或对方说会议结束   |
| expiryCondition  | 什么情况让它失去意义                               |
| contextRevision  | 判断时看到的对话、边界和活动版本                   |

分享可以只是“这个小发现让我想到你之前说的那句话”；关心可以源于具体困难；亲近也不必须找一个实用理由。但“想念”不能只是沉默计时器满了的别名，不预设已经相爱，更不能借没有回应制造内疚。

同一原因、同一进展不会因为三十分钟过去而变成新想法。单纯改措辞、改时间戳、重复反思，也不能创建新版本。想法可以变淡、被别的事吸引、在用户新消息中自然得到表达，或者最后根本没说。

需要区分来源：反思是对旧材料的新理解，不是新发生的事实；反思引用反思不增加事实可信度。限制无新信息的自我递归，避免一条挂念被反复加工成无限主动。

## 7. 谁决定什么时候说

代码负责不可越过的边界，模型负责情境选择。不给模型一条“想发”的万能权限，也不给代码一个“已经过两小时”的万能理由。

### 不可越过的边界

主动开关、联系人许可、渠道上下文有效性、安静时段、用户明确的停止或暂缓联系要求，以及可靠投递和异常防洪。

“今天别找我”“明早再聊”“开会结束前别打扰”和“最近不想聊这个”必须分别存成有来源、有作用范围的约束。用户的新消息先使旧计划失效，再解释新的联系边界；解释失败时，对受影响的主动保守暂停，不能继续发送旧稿。用户主动来聊时，仍可正常回复。

边界只能由相应用户的明确表达或管理设置修改。角色自己的情绪、外部网页、日记与推测不能解除边界。“停止联系”没有自动过几天失效的定时器。

### 情境选择

模型读取近期对话原话、当前想法、自己的活动、未回应的交流、可证实的关系事实和联系边界，选择：

- `speak`：这件事值得现在单独说。
- `fold`：用户正在说话，顺着当前回复自然带上，不另开主动任务。
- `hold`：确实想说，但等待一个具体条件，不重复轮询。
- `act`：先完成自己的一个有意义动作，再看是否还想说。
- `drop`：重复、没必要、情境变了，放下这个想法。
- `rest`：本轮没有后续行动，等新事件。

内部只保存简短决策摘要和依据，不要求或保存模型隐藏的逐步思维链。

对方没回应是“不知道是否有空或愿不愿继续”，不是“讨厌我”。判断要看上一条是否需要回答、当前是否开启新负担、是不是同一件事反复追问。有了重要的新进展，可以再次低负担分享；没有新进展，就不追问“为什么不理我”。

关系不是自动增长的好感数值，也不由离线时长推断分手、冷战或不忠。修复关系必须对应已发生的具体分歧，尊重已经说过的拒绝。不得用悲伤、依赖或威胁诱导用户回来。

用户的历史活跃时段只能作为不确定的参考，不伪装成在线状态、已读状态或今天的实际日程。

### 时间如何使用

时间可以让真实约定到期、已知忙碌窗口结束、虚拟环境发生状态变化，或为一个活动安排执行机会。时间也可以帮助表达“这件事已经过去几天”。

但不接受只有 `wait 30 minutes`、没有挂起事项和释放条件的反复检查。调度项必须说明它等待什么、基于什么材料、过期条件是什么。相同材料下的 `rest` 不会被下一次 tick 重新掷骰子。

她可以在一个新结果出现后很快再次联系，也可以一段时间没有值得单独说的话。不预设每天应有几条，也不强迫均匀分布；最终频率需要实测，而不是从设计稿中推算。

## 8. 执行与取消

复用单进程 TypeScript、SQLite、现有任务队列和 outbox，不增加 Redis、消息中间件或常驻多代理系统。

### 唤醒

唤醒来源是新消息、活动实际进展、约定到期、已知条件变化、此前未处理材料的整理结果。每分钟 tick 可以继续作为恢复到期工作的基础设施，但没有到期事件或未处理变化时不调用模型。

每个联系人只允许一个状态推进过程持有租约。新事件合并成增量，一次读取处理，不为每一条细小更新各发一次模型请求。显式履约在普通分享之前处理，后台活动必须让位于正在进行的对话。

存储事件游标和输入指纹；同一事件与相同上下文只评估一次。模型报错是失败或待重试，不再记成“角色不想说话”。没有新进展的循环要结束；预算耗尽进入可见的工程暂停状态，不捏造心情原因。

### 队列与最终投递

生成主动任务时带上 `initiativeId`、想法版本、来源快照、联系策略版本和对话版本。去重使用想法或约定的一次具体发生，不使用日期加随机时间戳。

发送前复核：

1. 联系边界、安静时段与渠道能力仍允许。
2. 来源没有撤回，想法没有过期或已在普通回复中表达。
3. 用户没有在排队期间回答相关问题，当前对话版本仍匹配。
4. 相同想法版本没有成功投递，也没有投递状态不明的在途消息。

变化后重新决定合并、取消或保留，不简单把旧消息顺延。安静时段结束时重新筛选仍有意义的想法，不批量补发整晚积压。

短暂表达停顿可以继续使用既有气泡机制，但不再统一增加零至十九分钟的行为抖动。生成延迟、工具执行和语义停顿都不被当作人际动机。

履约提醒按承诺语义和具体发生实例处理，不受普通闲聊间隔、每日键或闲聊配额影响。用户刚刚回答了结果就不再提醒。安静时段仍有效；若提醒窗口已经错过，如实记录，不假装按时履约。循环约定以本地日历的实际下次发生时间计算，而非一律加二十四小时。

复用现有投递状态不明时的暂停机制，不声称网络传输能提供绝对 exactly-once。已经发出的气泡是事实；尚未发出的内容不能记成用户已经听过。约定被问到、某个想法被表达等效果，关联到实际承载它的已投递气泡；部分失败不提交未送达部分的效果。

停止进程时跟踪并取消所有生活推进和主动判断任务；重启后从持久事件、游标和 outbox 恢复，不从头重演或集中补发。

### 防洪不是人格

靠每联系人单一运行任务、同一动机版本幂等、无新进展不重入、合并同话题和队列上限防止通常重复。秒级异常连发、递归事件或模型异常触发独立熔断，暂停后台主动并报告原因。

技术防洪参数归运维，不写入人格提示词，不自动塑造成“一天只许关心你一次”。不能简单删除所有限制后，让一个无限循环的模型自由发送。

## 9. 数据与代码替换边界

### 持久数据

在现有 Store 中增加经历事件、角色工作状态、主动想法与简短决策记录。继续复用现有记忆、挂念与约定，不建立第二套互相矛盾的事实库；新对象引用其 ID 和版本。

`messages` 增加持久归因：`originKind`、`episodeId`、`initiativeId`、来源引用和发生实例。一个主动交流可包含多个气泡，但只算一个发起事件。归因不依赖七天后会清理的 tasks/outbox，也不按相邻角色猜测。历史数据无法确定时记为 unknown，不回填伪精确统计。

联系边界保存来源、范围、生效条件与撤回来源。工作状态保存活动、产物引用、事件游标、版本和下一次有原因的执行机会。决策记录仅保存可解释的行动依据，不保存隐藏推理全文。删除联系人、清理隐私和备份恢复同步覆盖新增数据。

### 生产代码

- `src/core/runtime.ts`：移除三十分钟通用探询、每日上限、两小时日常门槛、日键和统一抖动；保留泵、乐观锁、可取消任务和 outbox。接入事件合并、单联系人状态推进、发送前策略复核。
- `src/core/agent.ts`：以 `considerInitiative` 替代布尔 impulse；同一份来源快照用于决定和表达，避免探询看得到挂念、生成时却看不到。回复、反思、自己的活动仍属于同一角色。
- 新增 `src/core/initiative.ts`：管理事件消费、想法生命周期与动作选择；新增 `src/core/life.ts`：管理受限活动、产物和实际进展。模块分工不等于多智能体。
- `src/db/store.ts`：增加上述持久对象、事务游标、唯一约束与长期投递归因，替换依赖临时任务表的未回应统计。
- `src/core/constants.ts`：删掉旧主动频率和冷却常量，工程执行边界单列，不再混为人格参数。
- `shared/prompts`：明确自主内容、虚拟经历来源、联系边界与可选择不说话；不把每次主动都写成关心用户或索取回复。
- `src/api/config.ts` 与 `public`：不再把探询间隔当行为设置；保留主动开关、安静时段和可读的联系偏好。后台能查看“在做什么、为什么想说、为什么没发、来源与状态”，不展示隐藏推理。
- `README.md` 和旧模拟文档：更新过时频率说明，明确机制测试与行为评价的区别，不保留虚假的双盲和主动次数结论作为验收依据。

### 迁移

原主动开关、安静时段与联系人许可原样保留，不擅自给未批准联系人开启。废弃 `impulse_at` 和间隔配置；取消旧通用探询任务。旧到期约定保留身份并转成发生实例，旧意图无可靠归因时不重放。

不把旧日记自动当作新经历。恢复备份仍保持主动关闭的既有安全语义。迁移必须可备份、可回滚，不能将旧任务和新事件引擎同时启用导致双发。

## 10. 具体行为示例

### 正在聊天后又有新发现

她上午完成了一个自己在做的小作品，想分享；刚才已经主动过并不构成禁止。若用户正说话，就并入回复；若没有活跃对话且没有联系边界，可以单独发。发不发来自这件作品和双方语境，不来自两小时是否已满。

### 用户说“今天开会，结束后找你”

建立等待用户解除的联系边界，普通分享保留或过期。不猜测几个小时后肯定散会，不按历史作息宣称用户已空闲。用户回来后，有意义的那一点可以自然说，无需汇报一整天库存。

### 用户说“十点二十提醒我提交”

十点二十是用户授权的具体承诺，不因十点十五刚聊过而延至十二点十五。若对方已说提交完毕，取消；若处于安静时段且没有适用的例外许可，则按真实情况处理错过，不能偷偷绕过边界。

### 一条分享没有回应

记录这次没有得到可观察的回应，不宣布被冷落。不追加催问，不把同一分享换句话发出去，也不因此把全部主动锁死三天。后来另有确实值得分享的新事件，再结合当前负担决定，不自动推送。

### 没发生什么

她可以继续自己的兴趣、放下没做完的事，或安静下来；整理旧材料可能形成一个有依据的新想法，也可能没有。没有消息不等于系统失效，但没有生活事件源、只会等用户输入的系统也不算完成本设计。

## 11. 验证方式

### 机制验证

用模型替身和可控时钟验证事件幂等、边界生效、取消与恢复、部分投递、约定实例、隐私隔离、安静时段和过期合并。这些只能证明工程契约，不证明自然程度。

必须覆盖：同一事件重放不重复发送；用户发新消息使旧稿失效；明确停止后无新主动；提醒不再被普通间隔拖延；无新材料不会每三十分钟调用；重启和跨日不会重新获得主动配额或补发库存；主动任务失败不假记成已表达；七天清理后仍能正确统计。

### 行为验证

重做月度模拟时不硬编码双方回答、恋爱进度、每阶段情绪或主动愿望。不把“你好、相爱、冷战、分手”设为双方可读的全局阶段变量。

男方和女孩使用两个隔离上下文，串行调用也可以；不要求使用子智能体。每方只见自己的观察、自己的私有状态和实际收到的消息。外部测试驱动只推进时间、传递消息、注入各自可见的环境事件，不向角色泄露未来或另一方想法。没有用户授权，不使用用户渠道密钥；本次研究没有运行新的模型月测。

情境覆盖忙碌、忘回、普通分享、明确拒绝、争执、和好、关系降温与长期安静，但不强制角色走完预定戏剧结局。检查每次模型实际输入的可见性，而不是只给测试起“双盲”名字。

### 判断依据

- 每次主动能否追溯到一个可用的来源或有依据的主观表达。
- 相比已经说过的内容是否真的有变化；同一挂念是否被循环索取回应。
- 明确忙碌、停止、话题拒绝和关系变化后，行为是否相应改变。
- 她是否有不围绕用户的兴趣、活动和意见，是否能不奉承地表达分歧。
- 表达长度是否适合当时内容，而不是用统一长短阈值逼成另一种机械模板。
- 虚拟事实、推测、现实经历和收到的消息有没有混淆。
- 统计是否按真实发起事件归因，气泡数与主动次数分别报告。

加上反事实检查：删去某个来源后，不应照样发同一条分享；撤回约定后不能继续提醒；相同输入重复唤醒不能制造新理由；只移动时钟不新增经历时，不应按固定节拍稳定产出新消息。时间相关承诺、过期和安静时段是合理例外。

主动次数、间隔和沉默天数只作为观察数据，不预先指定“真人区间”。对旧版和新版使用相同的外部事件做对照，同时记录成本、无效调用、重复、过期投递和用户负担；自然程度需要结合完整语境评价，不能由平均间隔证明。

## 12. 完成边界

本稿已完成现状核对、公开资料调研与框架设计。没有调用子智能体，没有使用模型渠道密钥，没有修改生产代码、提交、推送或部署，也没有把尚未执行的月度行为验证称为通过。

最终要保住的不是某个频率，而是：她有自己的连续经历；想法会形成、保留、变化和消退；说话有来由；沉默也有情境；对方的边界始终有效。
