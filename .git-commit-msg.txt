fix: teach weak proxy models reminders, mood pulses and bubble breaks

Second live round against the cheap glm-5.3-flash relay exposed three
more failure modes, all fixed without touching the good channel's
behavior:

- The model told users it "cannot send timed reminders" (it can - the
  open-loop scheduler does it) and then wrote memoryUpdates as bare
  strings that were silently dropped: "I'll remember" became a lie.
  parseMemories now accepts string entries as source-less
  interpretations; agent attaches the triggering user message as their
  source. parseOpenLoops keeps source-less loops through the shape pass
  and back-fills the same way. stated facts still require explicit,
  visible sources - auto-sourced entries are always downgraded to
  interpretation.
- Capability line pinned in the stable system prompt and chat.md:
  sticker objects and open-loop reminders are really sent by the
  system, never claim otherwise. The per-turn user-side format reminder
  now also names openLoops and moodPulse so instruction-blind models
  emit them.
- Bubbles that contain newlines ("- a\n- b" lists) are split into
  separate bubbles - one line, one WeChat message; beat pauses stay on
  the first piece. Prose fallback keeps splitting on blank lines.

Live-verified on the relay: the water reminder landed as an open loop
due 2026-10-26 08:00 with a real source id, both memories persisted,
moodPulse flowing every turn, list replies delivered as separate
bubbles.
